## Baseline invariants that must not break (contract summary)

These are “stop-the-line” constraints derived from the canonical baseline and are enforced throughout the tasks below:

- **MCP endpoints remain stable:** `POST /mcp/search`, `POST /mcp/fetch`, `GET /mcp/health`.
- **`/mcp/search` response schema remains stable:** top-level `{query, top_k, effective_search_ratio, results}`; per-result includes `{text, metadata, score, score_vector, score_fulltext, semantic_nodes, semantic_relationships}`; and `metadata` **must not** contain `embedding`.
- **`/mcp/fetch` response schema remains stable:** `{found, element_id, metadata?, text?, error?}`, and `metadata` **must not** contain `embedding`.
- **QA remains run-scoped + safe:** QA gating must remain functional; rollback must be scoped (no collateral deletes); QA artifacts must remain scrubbed of secrets.
- **Indexing remains safe + predictable:** prefer idempotent index scripts; avoid silent destructive recreation; detect config mismatches where possible.
- **Document↔Chunk linkage remains valid:** every ingested `Chunk` must be reachable from a `Document` via `(:Document)-[:HAS_CHUNK]->(:Chunk)`.

# B) Task Execution Notes

## Branch and PR hygiene assumptions

- **One task = one PR.** Use the Task ID in the branch name and PR title (e.g., `dr09/DR09-T07-make-ingest-script`).
- **Small, reviewable PRs:** avoid mixing refactors across concerns. If a PR touches more than one subsystem (ingestion + retrieval + ops), split it.
- **Always include in the PR description:**
  - Goal / scope
  - Files changed
  - Validation evidence (paste command outputs or CI links)
  - Risk/rollback notes
- **Keep mainline green:** `make smoke` is treated as the authoritative regression gate for every PR.
- **Do not “fix forward” on the same PR:** if validation fails and the fix is non-trivial, revert and split.

## How to avoid breaking baseline contracts

### MCP contract guardrails

- Do **not** rename routes or tool names. Maintain:
  - `POST /mcp/search`
  - `POST /mcp/fetch`
  - `GET /mcp/health`
- Do **not** remove or rename response fields:
  - `/mcp/search` must continue to return `score`, `score_vector`, `score_fulltext`, and semantic context arrays (`semantic_nodes`, `semantic_relationships`) even if internals change.
  - `metadata` must always include `element_id` + `labels`, and must never include the raw `embedding`.
- Prefer adding *new* optional fields only if necessary, and only after adding contract tests and documenting them. Otherwise treat the response JSON as frozen.

### Data integrity + rollback guardrails

- Keep ingestion **run-scoped**:
  - Every run must produce a reliable `ingest_run_key`.
  - QA and rollback must query by this key and must not “widen” scope.
- Treat rollback as destructive and high-risk:
  - Never delete nodes/relationships without a run key filter.
  - Add explicit tests or scripts that prove rollback does not affect prior runs.

### Index management guardrails

- Prefer Python scripts (`scripts/create_vector_index.py`, `scripts/create_fulltext_index.py`) over Makefile Cypher for normal operations.
- Keep idempotence: repeated runs should be safe.
- Fail fast on mismatches rather than silently drop/recreate indexes.

### Secret/log safety guardrails

- Maintain `scrub_object` (or equivalent) for:
  - QA artifacts
  - index script logs/artifacts
  - any structured logs that could contain env/config
- Never print secret values in tests or CI logs; test scrubbing using fake patterns.

## Validation discipline (per PR)

Minimum required per PR (map to DR_08 “minimum gate”):

1. `git status --porcelain` + `git rev-parse HEAD` (DR_08 A.1)  
2. `make smoke` (DR_08 B.6.1)  
3. If MCP touched: run DR_08 B.8.1–B.8.3 (health/search/fetch contract checks)  
4. If indexing touched: run DR_08 B.3.1–B.4 (ensure + verify indexes)  
5. If artifacts/logging touched: run DR_08 B.6.2 + B.10.2 (scrubbing scans)

For high-risk PRs (pipeline swaps, schema changes), run the **full gate** described at the top of DR_08.
